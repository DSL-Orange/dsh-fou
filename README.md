# dsh-fou · 浮游

> **浮游是 DSH 之上的一层悬浮容器。**
> **它不属于任何一个会话 —— 它跟着你。**

**包名** `dsh-fou`（旧名 `@local/dsh-fou` / `@local/dsh-courier`）· **显示名** 浮游 · **英文** Fou

> **状态：第一阶段完成（0.2.0）。** 核心能力已闭环、协议已定；接口仍可能微调。

## 它是什么（以及它为什么长这样）

浮游是**贴着 DSH 走的一层界面**。三句话定它的位置：

| 原则 | 意思 |
|---|---|
| **定位 = 跟人** | 容器跟着**人**走，不跟着会话走。换到哪个会话，它都还在原地。 |
| **边界 = 辅道** | 不跟 DSH 的主道抢。**官方做容器，浮游也做容器 —— 但只为一件事：把人留在原地。** |
| **从属 = 借宿** | 它住在 DSH 里。**借宿不是永久，是当下的正确姿态。** |

**它不是什么**：

- **不做工作台** —— 一个小球就够了。
- **不做标签页** —— **一次只看一件。**
- **不替代浏览器** —— 装 URL 是为了"带你去现场"，不是为了"替代你上网"。

## 它现在能做什么

| 能力 | 说明 |
|---|---|
| **三形态** | **圆球 / 呼机 / 全窗** —— 可拖动、可记忆、任意非交互区都能拖 |
| **聊天** | 不离开当前页面，给**当前会话**发一条消息 |
| **穿越** | 在会话之间移动（左键） |
| **开间** | 一个**只装一件**的容器：能装**网页**、**文件**、**插件界面**（右键） |
| **最近打开** | 回到刚才看过的东西（按模式分开记） |
| **挂靠** | 插件可以把界面**挂进开间**（硬挂载），或给浮游一个**动作**（遥控），或报一条**状态简讯**（`brief`） |
| **应用槽位** | 胶囊左栏可切到报了 `brief` 的插件 —— 比如地颂：左栏 `♫`、右栏歌名、**点胶囊就是播放/暂停** |
| **挂板** | **只装「挂表」** —— 验收表 / 批注表 / 回执。**普通文件走浏览。** |
| **编辑器** | 编辑即保存、发送即落稿（**所写即所发**） |

### 左右键的名字

| 键 | 名字 | 管什么 |
|---|---|---|
| **左键** | **穿越** | 人怎么动 |
| **右键** | **开间** | 框怎么开 |

## 三化（我们的叫法）

浮游的架构分三层。**这三个词是我们自己的叫法，不是行业标准术语。**

| 层 | 中文 | 英文 | 层级 | 判断依据 |
|---|---|---|---|---|
| **最抽象** | **模式化** | **Method** | 浮游本体 > 开间界面 > 接口协议 | **换了宿主还成立吗** |
| **中间** | **模块化** | **Model** | 浮游开间 > 浮游功能 > 浮游挂载 | **能接入能取出吗** |
| **最具体** | **模具化** | **Mold** | 开间协议 > 挂载协议 > 优化协议 | **长成什么样、还能不能改** |

> **模式化是"换了宿主还成立"；模块化是"能接入能取出"；模具化是"长成什么样、还能不能改"。**

**而它们背后有一个被归纳出来的形状**（同一个模式出现了两次）：

| 第一次（挂表） | 第二次（挂靠） |
|---|---|
| ① **挂板协议** | ① **开间** |
| ② **链接协议** | ② **硬挂载** |
| ③ **模表协议** | ③ **软优化** |
| **= ④ 挂表协议** | **= ④ 挂靠** |

> **① 往哪挂 · ② 怎么挂上去 · ③ 挂上去怎么长得好看 · ④ 三者合成的契约**
> **——这个"①②③=④"的形状，就是模具的形状。**

## 安装

**需要**：DSH 0.2.x

**本仓库还没有发布到 npm** —— 所以还**不能**在「添加插件」里键入 `dsh-fou` 装。

**但现在有两条能用的路**（都在 DSH 的「插件页 → 添加插件」里，它会自己登记 `bundles`）：

### 路 A · 压缩包（推荐，最不容易出错）

1. 拿到 `dsh-fou-0.2.0.tgz`（或自己 `npm pack` 打一个）
2. **插件页 → 添加插件 → 粘这个 tgz 的绝对路径** → 安装
3. 重启 DSH

### 路 B · 本地目录

1. 把仓库放到你机器上任意位置
2. **插件页 → 添加插件 → 粘那个目录的绝对路径** → 安装
3. 重启 DSH

### 路 C · 手动接进 profile（开发用）

**⚠ 不推荐** —— 漏登记 `bundles` 就会"页面根本没请求它"。只有改源码时才用这条。

1. 建链接：`node_modules/<包名>` → 源码目录
2. 在 profile 的 `package.json` 里登记：
   - `dependencies` 加 `"dsh-fou": "link:<你的路径>"`
   - `dsh.profile.bundles` 数组里加 `"dsh-fou"`
3. 重启 DSH

> ⚠ **改 `bundles` 会让 DSH 重新加载插件列表 —— 改错可能导致 DSH 起不来。**
> **改之前先备份 profile 的 `package.json`。**
